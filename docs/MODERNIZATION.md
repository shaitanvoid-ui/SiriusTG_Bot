# SIRIUS — модернизация 01.10.2026

Бот обновлён до актуальных стабильных зависимостей. Пользовательский интерфейс
и административные карточки используют общий слой оформления. Фирменные
фотографии и обложки по просьбе владельца удалены: интерфейс строится из
Rich Messages, текста и inline-кнопок.

## Что изменилось

- Главная показывает баланс, уровень, команду и персональное следующее доступное действие.
- «Мой день» собирает бонус, бесплатное вращение, остаток кликов и новые задания.
  Завершённые действия не предлагаются повторно. Недоступная проверка bio и
  перезарядка кликера учитываются при выборе следующего действия.
- Карточки отображаются как нативные заголовки, таблицы, подзаголовки,
  раскрывающиеся условия и примечания. Известное отсутствие поддержки Rich API
  позволяет вернуться к исходному HTML. Произвольные сетевые ошибки не вызывают
  повторную отправку сообщения.
- Доступные награды и основные действия имеют цветовые акценты. Полученные бонусы
  и исчерпанные лимиты используют настоящий `DisabledButton`.
- Реферальную ссылку можно скопировать через `CopyTextButton` без дополнительного сообщения.
- Дневной сброс использует нативное отображение времени. Расчёты суток и интерфейс остаются московскими.
- Переход в другой раздел очищает незавершённый диалог. Неизвестные и устаревшие
  callback'и получают ответ; недоступные сообщения не запускают операции экономики.
- Платное вращение требует подтверждения показанной цены. Подтверждение живёт
  две минуты, аннулируется после выхода из раздела или изменения цены и имеет
  уникальный токен на пользователя. Уникальный индекс в БД защищает от повторного
  списания при конкурентной обработке одинакового запроса.
- Результат вращения фиксируется перед анимацией: её задержка не удерживает
  write-lock SQLite, а ошибка Telegram не отменяет уже сохранённый результат.
- Вечерние напоминания выключены для каждого пользователя по умолчанию.
  Их можно включить в уведомлениях. Они отправляются тихо, максимум одна попытка
  в московские сутки, только при неполученном бонусе, выполненных гейтах и
  отсутствии недавней активности. Заблокированные и удалённые пользователи исключаются.
- Удалён Telegram-хук завершения работы Claude (`.claude/notify-telegram.ps1`
  и его настройка `Stop`). Именно это уведомление имел в виду владелец.
  В исходном `_on_startup` бота отправки уведомлений не было; технические логи,
  алерты ошибок воркеров, бэкапы и ежедневный дайджест сохранены.

Существующие ставки, спонсоры и настройки экономики сохранены. По отдельной
команде владельца его профиль и личная история сброшены (подробности ниже).
Вывод подарков и отдельный антифрод-этап не добавлялись.

На момент сборки тег `python:3.14.8-slim` ещё отсутствовал в Docker Hub.

`requirements.lock` и `requirements-dev.lock` фиксируют также транзитивные
зависимости и SHA256. Docker устанавливает пакеты с `--require-hashes`.
Lock-файлы рассчитаны на Python 3.14 / Linux и получены через uv 0.11.18.

Пересоздание lock-файлов:

```powershell
uv pip compile requirements.txt --python-version 3.14 --python-platform linux --generate-hashes --output-file requirements.lock
uv pip compile requirements-dev.txt --python-version 3.14 --python-platform linux --generate-hashes --constraint requirements.lock --output-file requirements-dev.lock
```

## Измерение загрузки настроек

Одинаковые Python 3.14.7, SQLite и данные; 60 повторов на вариант. Сравнивалась
холодная загрузка 12 общих настроек с исходным `SettingsService` из резервной копии.
Новая версия заранее загружает конфигурацию одним запросом. Это измерение слоя
настроек, а не задержки Telegram или производительности бота под боевой нагрузкой.

| SELECT на холодную загрузку | 12 | 1 |
| Медиана | 14,797 мс | 2,958 мс |

SHA256 исходного файла для сравнения:
`008b1d7b45d44f6159f1751f421daf40a3feed57ee7487084676ff97d38fd8bd`.
Проверка воспроизводится через `tests/performance_probe.py` с архивом исходников.
Тёплые чтения используют TTL-кэш; разные БД, значения по умолчанию, незавершённые
транзакции и savepoint'ы изолированы отдельными регрессионными тестами.
Обновление `last_seen_at` ограничено одним разом в минуту для неизменившегося профиля.

## Запуск и откат

Перед первым запуском нового образа сохранить защищённую резервную копию БД и
ключа шифрования. `docker compose up -d` применит миграции через entrypoint.
Не запускать параллельный экземпляр polling для того же токена.

```powershell
docker compose build bot
docker compose up -d
docker compose logs --tail 100 bot
```

Для отката остановить бота, выполнить `alembic downgrade 0011` новым образом
и вернуть предыдущий код/образ. При downgrade удаляются только новые маркеры
напоминаний и токены подтверждений; история вращений и исходные данные сохраняются.
Восстановление защищённой резервной копии — альтернативный полный откат.

Параметры интерфейса: `RICH_MESSAGES=true`, `POLLING_CONCURRENCY=32`.
Настройки напоминаний редактируются из админки через группу `daily`:
`daily.reminders_enabled`, `daily.reminder_hour_msk` (10–21),
`daily.reminder_batch_size` (1–1000). Дефолт — 20:00 МСК.
Неоднозначно неудавшаяся отправка напоминания не повторяется в этот день,
поскольку у Telegram нет ключа дедупликации для `sendMessage`.
